Use the complete catalog with your agent

Clone once, search locally, and build retrieval workflows from source-backed records. The full catalog is available without an account or API key.

AGENTS.md · 中文指南

1. Clone the data

git clone https://github.com/reacher-z/Awesome-CUA.git
cd Awesome-CUA
git rev-parse HEAD

Read data/catalog.jsonl directly, or use the commands below with Python 3.11+. Search and export use the standard library; no model service or dependency installation is needed. Keep the Git commit as your source snapshot identifier.

Versioned data snapshots provide a complete data ZIP for repeatable ingestion. Verify SHA256SUMS and retain release-manifest.json with the source commit and catalog fingerprint. The bundle includes catalog, RAG, citations and topic subsets; repository CLI commands below require the source clone.

2. Ask a focused question

python3 scripts/catalog.py search "grounding" --kind model --status curated --json
python3 scripts/catalog.py search --kind dataset --environment android --status curated --limit 0 --json
python3 scripts/catalog.py search --kind paper --status curated --topic reinforcement-learning --limit 0 --json

Search is literal and uses AND across terms. Use aliases when a query is too narrow; --limit 0 returns all matches. Review status and platform/topic tags describe what the catalog has checked.

Retrieve a record by ID

python3 scripts/catalog.py get arxiv:2404.07972 --json
python3 scripts/catalog.py get arxiv:2404.07972 --related --json

For a field overview, open the topic directory. Its JSON manifest provides exact reviewed member IDs, complete-record subsets, citations and file fingerprints. Pass a downloaded records.jsonl subset to export_rag.py --input to build a focused retrieval corpus. Topics overlap and do not imply dependencies between their members.

Exact lookup returns the original record. Related lookup adds reviewed links in both directions, with their source evidence. Unknown and scope-excluded IDs return distinct nonzero exit codes and do not masquerade as active records.

Resolve a recorded former repository name

python3 scripts/catalog.py get github:mnotgod96/appagent --json
python3 scripts/catalog.py search "https://github.com/mnotgod96/AppAgent" --json

These commands return the canonical AppAgent record. Use its returned id for joins and retrieval-store updates. The repository identity observations bind former and current names to the same numeric GitHub repository ID using paired official API receipts. They are dated identity evidence; they do not create extra resources or change review status. Aliases and their evidence are included in catalog and RAG records.

Each resource page has a record.json file for direct HTTP retrieval. Scope-excluded records return an explicit excluded decision rather than an active record. Example JSON.

3. Connect a RAG pipeline

python3 scripts/export_rag.py --output dist/rag-documents.jsonl
python3 scripts/export_rag.py --include-metadata --output dist/rag-all-records.jsonl
python3 scripts/catalog.py build

Ingest the text field and retain the metadata object. Use id as the stable upsert key. Start with the reviewed export; the full export also includes bibliography entries awaiting relevance review. SQLite is generated at dist/catalog.sqlite.

4. Export paper citations

python3 scripts/export_citations.py --format bibtex --output dist/citations.bib
python3 scripts/export_citations.py --format csl-json --output dist/citations.csl.json
python3 scripts/export_citations.py --id arxiv:2404.07972 --format bibtex

The default exports reviewed papers and surveys. Add --include-metadata for all active bibliography entries. Unknown venues and identifiers are omitted; original publication dates and version-update dates remain separate. Individual paper pages provide their own BibTeX and CSL JSON downloads.

Select the publication edition

python3 scripts/export_citations.py --edition publication --format bibtex --output dist/publication-citations.bib

This selects reviewed records with publication metadata. The publication uses its own title, authors, venue and date; the default arXiv citation retains its original preprint version. Publisher-only records use their publication in either mode. Year-only and month-only dates stay partial.

Ready-to-use downloads

Open the data hub · Complete download manifest

The manifest lists each main export with its count, unit, scope, byte size and SHA-256. Counts describe overlapping populations; verify the file fingerprint before ingestion and keep catalog_sha256 with your retrieval snapshot.

  • Complete catalog — Every active resource and its full source record.
  • SQLite database — Resources, facets, relations, and full-text search.
  • Reviewed retrieval documents — One document per reviewed resource, including citations and provenance.
  • All retrieval documents — Includes metadata-only entries with their review state intact.
  • Reviewed paper citations · BibTeX — Recorded authors, dates, and paper versions.
  • Reviewed paper citations · CSL JSON — Structured bibliography for reference managers.
  • RAG export manifest — Counts, SHA-256 fingerprints, and the catalog snapshot fingerprint.

Keep answers traceable

Curated means AI-assisted editorial review against a primary source. Metadata verified means bibliographic identity was checked; it does not establish relevance or validate findings. Cite the primary resource and catalog permalink, retain dates and recorded versions, and preserve unknown values. Papers, code, datasets, and checkpoints can be related records rather than independent projects.

Metadata-only entries may await their first review or remain on hold after source reading. Recorded hold reasons appear in the coverage ledger. Held records remain outside the reviewed retrieval export.

The exports contain catalog metadata and original annotations. Paper full text, model weights, and training examples remain with their publishers. Code, data, weights, and document licenses are separate.

Update and reconcile

Pull a newer Git commit or fetch a new manifest. Compare record_sha256 for changes and reconcile missing IDs against the complete catalog and scope-exclusion ledger. An absent ID may represent a reviewed scope decision; do not leave stale retrieval documents silently active. Discovery is scheduled every two hours, with actual outcomes and gaps recorded on the updates page.
